# genbeya_core

Genbeya Mobile's Git core: the Git operations the app needs, as whole tasks over libgit2, bound to Dart with flutter_rust_bridge. Built for [[GM-2]]; the design is in `docs/Architecture.md` ("Git on the device", "Where edits go") and `docs/Architecture/Call-chains.md`.

| Part | Is |
| --- | --- |
| `src/git.rs` | The operations, in plain Rust; nothing here knows about Dart |
| `src/api/git.rs` | What Dart can call: thin wrappers, run off the UI thread, Futures and Streams on the Dart side |
| `src/frb_generated.rs`, `lib/src/rust/` | Generated by `flutter_rust_bridge_codegen generate` (config: `flutter_rust_bridge.yaml` at the repository root) |
| `tests/flows.rs` | A phone and a teammate against a bare remote, on this machine |
| `../rust_builder/` | cargokit, as `flutter_rust_bridge_codegen integrate` generates it: builds this crate inside Flutter's Android (Gradle) and iOS (CocoaPods) builds |
| `test/native_bridge_test.dart` | The same library driven from Dart through the bridge, on the host |

Versions: git2 0.21.0 (libgit2 1.9.7 via libgit2-sys 0.18.8, vendored), OpenSSL 3.6.3 (vendored, openssl-src 300.6.1), libssh2 (libssh2-sys 0.3.4), flutter_rust_bridge 2.13.0.

## The API

| Call | Does |
| --- | --- |
| `clone_repository(url, dir, branch?, depth?, remote, operation_id)` → progress stream | One branch (the remote's default when none is given) into a new folder, `depth` commits deep; `core.symlinks=false` is set before the checkout, so links arrive as plain files; no submodules. Cancelled or failed clones leave no folder. Read `head` afterwards |
| `head(dir)` | Branch, commit, upstream, ahead and behind, paths not committed, shallow or not |
| `commit_files(dir, paths, message, identity)` | Commits the working tree's state of those paths on the checked-out branch; no staging step |
| `commit_onto_branch(dir, branch, changes, message, identity)` | Writes files into another branch's tree in memory and moves that branch; the checkout never changes. For the content branch and pull request replies. A branch only on the remote is created from it, tracking it. The checked-out branch is refused |
| `fetch(dir, extra_branches, remote, operation_id)` → progress stream | Fetches the configured branches; extra ones (the content branch) join the remote's configuration |
| `rebase_onto_upstream(dir, identity, resolutions)` | Local commits onto the upstream, in memory: `UpToDate`, `FastForwarded`, `Rebased`, or `Conflicts` with each path's ancestor, ours (upstream) and theirs (the local commit) and nothing changed. Passing resolutions by path for that commit finishes it |
| `push(dir, branch, remote)` | Never forced: `Pushed`, `UpToDate`, or `Rejected` when the remote has commits the branch lacks |
| `log_path(dir, path, max)` | The commits of HEAD that changed a path, newest first |
| `diff_from_merge_base(dir, source, target)` | Changed files (renames found) and the patch from where the branches meet, with the indent heuristic; identical to `git diff -M --full-index` in the test |
| `merge_conflicts(dir, source, target)` | The paths a merge would conflict in, worked out in memory |
| `clear_stale_locks(dir, older_than_seconds)` | Removes `*.lock` files a killed sync left in the Git directory |
| `set_ca_locations(file?, dir?)` | Where OpenSSL finds CA certificates; the app passes `/system/etc/security/cacerts` on Android |
| `cancel_operation(id)`, `core_version()` | Stop a clone or fetch; versions for bug reports |

Errors are typed (`CoreError` in Dart): `HostKeyUnknown { host, fingerprint }` (an SSH host key not in `trusted_host_keys`: ask the user, retry with it), `AuthFailed`, `Cancelled`, `InvalidPath` (Genbeya's path rules), `InvalidArgument`, `Git`, `Io`. Credentials are handed out once per kind, so a wrong token fails instead of looping.

## Building

```bash
cd native/genbeya_core
cargo test                         # the flows; the HTTPS test is ignored by default
SSL_CERT_FILE=/path/to/ca.pem cargo test --test flows -- --ignored --nocapture   # real HTTPS clone
cargo build --release --lib        # then, from the root: flutter test test/native_bridge_test.dart
```

`flutter build apk` builds the crate for each Android ABI through cargokit; it needs the Rust targets (`rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android`) and the NDK Flutter names (28.2.13676358). iOS needs `aarch64-apple-ios`, `aarch64-apple-ios-sim` and `x86_64-apple-ios`. CI adds all of them. After changing `src/api/`, run `flutter_rust_bridge_codegen generate` (2.13.0) at the root.

## What broke, and the fix

- **git2 0.21 changed accessors** (`shorthand`, `path`, `summary` now return `Result`); adapted.
- **Borrowed callbacks**: progress closures and the cancellation flag had conflicting lifetimes in `RemoteCallbacks`; the flag is now shared as an `Arc<AtomicBool>`.
- **Cancellation** arrives from libgit2 as a callback error (class 26), not `GIT_EUSER`; the operation's flag decides that it was a cancel.
- **Single-branch clones** couldn't track a fetched content branch ("could not determine remote"): extra branches are now added to the remote's fetch refspecs.
- **Shallow clones** don't work over libgit2's local transport; the test uses `git daemon` (the smart protocol, as HTTPS and SSH are).
- **flutter_rust_bridge** returns only the stream for functions that take a `StreamSink`, dropping their result: clone and fetch return `()` and the app reads `head` afterwards. Enums with data need `freezed` and `build_runner` as dev dependencies.
- **The analyzer** read cargokit's build tool, which has its own packages: `native/**` and the generated `lib/src/rust/**` are excluded in `analysis_options.yaml`.

## Not verified here

- **Real phones**: nothing ran on an Android phone or an iPhone; the APK builds and contains the library for every ABI, and the spike screen (Spikes → Git core) is ready for a device: clone, commit a test file, sync, with timings.
- **iOS**: can't be built on Linux. CI's macOS job builds it with the Rust targets added; vendored OpenSSL and libssh2 for iOS are the likeliest trouble.
- **Android CA certificates**: `set_ca_locations(dir: /system/etc/security/cacerts)` follows OpenSSL's hashed-directory format, which Android's store uses, but no HTTPS clone ran on a phone.
- **SSH** against a real server: the code path (key from memory, host key fingerprint check, `HostKeyUnknown`) compiles and is covered by types only; this container has no SSH server and no outbound SSH.
- **Push over HTTPS with a token** to a real forge, and the change ID (GM-19).

## Recommendation (D3)

Keep the Rust core. Within the two-day limit it clones (shallow, over HTTPS), commits without staging, commits onto a branch without a checkout, rebases in memory with conflicts reported and resolved, pushes without ever forcing, and builds into the Android APK for every ABI, driven from Dart through the generated bridge. git2dart isn't needed. Two things to watch: the +7.6 MB per ABI (OpenSSL is a large part; a smaller TLS backend is a later optimisation), and the first iOS build in CI.
