How mobile edits reach everyone, without ever losing one. See [[Architecture#where-edits-go]] and [[Experience#sync-and-changes]].

- [ ] Every save is a commit named after the change and the task, with the repository's identity
- [ ] Where commits go: the content branch for its areas, else asked on the first edit with the checked-out branch offered; a refused push offers to move the unpushed commits to `mobile/<handle>` (D5)
- [ ] Sync: fetch, rebase, push, one at a time per repository; pull to refresh; optional automatic sync
- [ ] Genbeya merge for task and pull request files: frontmatter per key, signed lines from both sides; conformance cases for it
- [ ] Rescue branch `mobile/rescue/<handle>-<date>` when it still conflicts: pushed, a banner of what differs until its commits are upstream, then an offer to delete it (D6)
- [ ] **Changes**: unsynced commits, undo the last ones before they are pushed
- [ ] Write journal: a write and its commit as one unit, recovered on the next start
- [ ] Never force; retry a rejected push from fetch, up to 3 times; rebase in memory
- [ ] Renumber a local, unpushed task whose ID a teammate took meanwhile, and the references to it in local commits
- [ ] Renumbering a task also moves its `.images/<ID>/` folder and rewrites its image references ([[Attached images]])
