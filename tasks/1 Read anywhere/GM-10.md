Find anything, and open what others share. See [[Experience#search]] and [[Experience#sharing-and-links]].

- [x] Search field in every screen's top bar: names first, full text below, grouped by kind (from Wiki and Tasks; match case, whole word and regular expressions as on desktop)
- [x] Full-text search over the clone's objects in the Rust core (off the UI thread), checked against `git grep`, with excerpts as `search-engine.ts` makes them
- [x] `genbeya://open?…` links registered on Android and iOS, parsed with the desktop's strict rules (`genbeya_link.dart`, conformance cases); open the clone with that remote or offer to clone, then the item
- [x] **Share Genbeya link** and **Share web link** through the share sheet, on pages and tasks (web links per forge on the branch the file lives on: `webUrl` ported)

Built (2026-11-22): search from the Wiki and Tasks top bars (names as you type, full text below, with match case, whole word and regular expressions); the core searches the clone's objects as `git grep` does (a flow test compares them). Genbeya links open the item in the matching clone, or offer to clone it first; pages and tasks share Genbeya and web links. Files and commits a link names say they open in Code ([[GM-17]]).

To try a link on Android without a chat app: `adb shell am start -a android.intent.action.VIEW -d "genbeya://open?remote=https://github.com/genbeya/genbeya.git\&task=GENBEYA-12"`.

On the Pixel (2026-11-22, CI run 42): search, sharing and the rest work, but a shared `genbeya://` link isn't tappable: chat apps linkify only http and https, and linkify the remote inside the Genbeya link instead. Meanwhile: **Open a link** on the start screen (the clipboard prefilled) opens a pasted Genbeya link, or a forge web link (GitHub, GitLab, Bitbucket), which chats do linkify: the file, task or page in the matching clone (branch names with slashes resolved against the clone's branches), or an offer to clone. The lasting fix, links on an https domain the apps verify, is a decision for the maintainer.
