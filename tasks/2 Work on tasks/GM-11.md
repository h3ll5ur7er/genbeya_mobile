How mobile edits reach everyone, without ever losing one. See [[Architecture#where-edits-go]] and [[Experience#sync-and-changes]].

- [x] Every save is a commit named after the change and the task, with the repository's identity (`ContentWriter`)
- [x] Where commits go: the content branch for its areas, else asked on the first edit with the checked-out branch offered (`startOwnBranch` for `mobile/<handle>`); a refused push offers to move the unpushed commits to `mobile/<handle>` (D5; `moveToOwnBranch`, end to end against a remote with a protected `main`)
- [x] Sync: fetch, rebase, push, one at a time per repository; pull to refresh (Tasks) and the sync badge (Wiki, Tasks)
- [ ] Optional automatic sync a few seconds after an edit
- [x] Genbeya merge for task files: fields per key, labels as a set, both sides' comments and time log entries (`task_merge.dart`; desktop has no such merge, so tests pin the rules, and the output is written by the conformance-checked task engine). Pull request files follow with [[GM-19]]
- [ ] Rescue branch `mobile/rescue/<handle>-<date>` when it still conflicts: pushed, a banner of what differs until its commits are upstream, then an offer to delete it (D6)
- [x] **Changes**: unsynced commits per branch, sync with what it did in words, undo the newest before it is pushed, move refused commits to a branch of one's own
- [x] Write journal: a write and its commit as one unit, recovered on the next start; on resume, `status` finds a write left uncommitted
- [ ] The app's own writes update the repository model directly ([[GM-7]])
- [x] Never force; retry a rejected push from fetch, up to 3 times; rebase in memory
- [ ] Renumber a local, unpushed task whose ID a teammate took meanwhile, and the references to it in local commits
- [ ] Renumbering a task also moves its `.images/<ID>/` folder and rewrites its image references ([[Attached images]])

Built (2026-11-23): the core rebases any branch in memory (the content branch without a checkout), takes resolutions per replayed commit and path, and creates, moves and pushes branches (`set_branch`, `branch_status`, `unpushed_commits`; flow tests). `ContentWriter` commits each save where its area lives, with a journal for the working tree; `SyncManager` fetches, rebases with the Genbeya merge, keeps what can't merge on a pushed `mobile/rescue/<handle>-<date>` and puts the branch back to the remote, pushes, and retries a rejected push from fetch. End to end against real repositories through the core (`test/sync_flow_test.dart`): a task both changed merges, a page both changed goes to the rescue branch, a write stopped halfway is committed. Comments' add, edit and remove are ported for the merge and [[GM-13]] (conformance cases).
