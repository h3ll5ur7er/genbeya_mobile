The screen a repository opens on. See [[Experience#today]].

- [x] My open tasks, in-progress first, overdue in red
- [ ] Pull requests waiting for my verdict, and mine with news (once [[GM-20]] is there)
- [x] Recent mentions of my handle
- [x] Checklist items with due dates in my tasks
- [x] Empty state that explains how "me" is found when the identity matches no one

Built (2026-11-26): `lib/managers/today.dart` (`buildToday`) and the **Today** tab, which a repository now opens on.

- **My tasks:** assigned to me by handle, name, email or alias, not in the last workflow state; furthest along first, then by due date (a date field's), then as the board sorts. Overdue in red, due within two days in yellow, as desktop marks them.
- **Checklist:** open task list items with a date (Genbeya's date rule), in my tasks or mentioning me in other tasks and in pages; soonest first, outside code blocks.
- **Mentions:** others' comments mentioning me (by handle or alias, as Genbeya's renderer resolves them), newest first with their dates; then task descriptions, and pages found by a search for `@handle`. At most 30.
- **Nobody matched:** an explanation and **Set my name and email**, after which the repository is read again.

Pull to refresh syncs. Pull requests wait for [[GM-20]].

To try on the phone: open a repository (it opens on Today); with your Git name matching someone in the people list, check your tasks, an item `- [ ] … 2026-11-25` in one of them, and a comment mentioning you written on desktop; then set a name that matches nobody.

Fixed after the first try on the phone (2026-11-26): Today sometimes missed a checkbox ticked or a line edited just before. Reads of the repository now run one after the other, so an older read that finishes later can't overwrite a newer one; a change made on a task goes on when its screen is left at once (it was dropped, or failed without its screen); Today is worked out again whenever its tab is shown; and a new session (after setting the identity) starts every tab afresh.

The cause, found on the second try (2026-11-26): Today's change listener called `setState(() => _today = _compute())`, whose closure returns the Future; Flutter's debug build throws then, after the assignment but before scheduling the rebuild, so Today showed its old result until something else rebuilt it (another tab). `test/today_follow_test.dart` follows the phone's steps and failed before the fix.
